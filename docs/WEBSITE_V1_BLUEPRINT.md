# Personal Observatory · Version 1.0

第二版网站的第一个可交付版本。基于 2026-10-26 至 27 日的用户叙述与现有源码；不是对未提供聊天记录的推断。

## 目标与读者

面向同行、导师、跨领域合作伙伴，以及因一个问题而产生共鸣的读者。首次访问的路径是：认识这个人 → 发现共同问题 → 阅读或体验真实内容 → 找到交流入口。

## 第一版的取舍

- 保留 Observatory 名称、衬线字体、克制的青绿色、研究问题、项目记录、知识关系和所有原有链接。
- 首页不再重复罗列学科、五个项目和全部子系统；身份与思考置于作品之前。
- 原首页完整保留在 `/observatory/`，供深度探索；旧研究、项目、Lab、Knowledge、Signals、Archive 路径不迁移。
- 首页不再把 2026 年 7 月的 Signals 称为最新动态。现有 Signals 仍可通过探索菜单访问，来源核实作为后续编辑工作。
- About 从占位页面改为有事实依据的个人介绍。

## 页面蓝图

### 首页 `/`

1. 身份：Carry Lewis，医学生；医学、工具创造、人的境况。两个入口：阅读思考、查看作品。
2. 个人问题地图：理解生命 / 将理解付诸创造 / 面对限制与意义。地图节点是页面锚点，支持触摸和键盘，无悬停专属内容。
3. 正在追问：三个跨领域问题，每个都有独立的 About 锚点、现有研究或项目入口；不伪装成已有长文。
4. 代表作品：ECG 和 Labwise。ECG 可体验；Labwise 明确是需本地运行的教师试点。使用仓库已有真实截图。
5. 开篇阅读：根据用户提供的认识方法整理的短文，明确是本站开篇而非学术成果。
6. 继续探索：已有研究、知识与实验入口。
7. 交流：仅使用已公开的 GitHub 个人主页；不从账号信息提取私人邮箱。以后由用户补充联系方式。

### 思考 `/thinking/`

首页开篇文章 + 三条问题线索 + 已有研究入口。暂不建立空的宗教、跑步、阅读文章分类，不制造阅读量、成绩或成果。

### 开篇 `/thinking/how-i-explore/`

第一人称方法随笔：观察、提问、理解、创造、反思；基于用户提供的方向编辑。不替用户断言宗教身份、具体教义立场、学术成果或人生经历。

### 作品 `/projects/`

保留完整项目目录与详细记录，更新介绍语，明确开发中与原型的区别。现有演示和下载入口不丢失。

### 关于 `/about/`

医学 / 构建 / 长跑 / 信仰与阅读的连续叙述；公开的是兴趣与方法，不公开用户未主动选择披露的成绩、孤独或执行力等评价。

## 设计与交互

- 纸白背景、墨色文字、青绿色链接；从仪表盘感转向可阅读的个人刊物，延续第一版字体与图谱语言。
- 内容宽度受限；中文正文使用本机中文字体，短标签辅助英文。遗留技术文档保留原语言，不提供失真的语言切换按钮。
- 导航：观测站、思考、作品、关于；探索菜单提供研究、知识、实验、Signals、Archive、第一版。
- 目录节点可点击，页面标题层级正确，所有控件可键盘操作；菜单 Escape/外部点击关闭、当前页标识、移动端自动收起。
- 减少动态效果；尊重 reduced-motion；移动端使用单列，避免依赖 hover。

## 内容维护入口

- `src/data/portrait.ts`：个人叙述、问题线索、精选作品的编辑说明。
- `src/data/profile.ts`：全站品牌、导航、元信息。
- `src/data/projects.ts` 及 `content/projects/`：已有项目事实。
- 新文章须注明发布日期，明确事实/个人判断/尚待回答的问题。没有真实内容不生成分类页。

## 验收与交付

构建与类型检查；导出页面内部链接和锚点检查；桌面和手机浏览器检查导航、项目与页面宽度。GitHub 独立分支与 PR 保存可审阅版本，保留主站部署工作流和 CNAME。未经真实浏览器验证的部分须明确报告。
